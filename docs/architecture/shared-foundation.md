## 2. Canonical Specification Inventory

### 2.1 `design_tokens.json` (v1.1.0 — **Implemented**)
Validated strictly at generation time by `validateDesignTokens()` in `scripts/sync_foundation.mjs`:
- **Colors**: `primary`, `secondary`, `surface` (12 light/dark canvas, subtle, card, elevated, border, divider keys), `text` (8 light/dark keys), and `semantic` (`income`, `expense`, `transfer`, `success`, `error`, `warning`, `info` with `on*` and light/dark `*Container` pairs).
- **Typography**: `fontFamilySerif`, `fontFamilySans`, `fontFamilyMono`, plus 10 scale roles (`display`, `heading`, `title`, `body`, `bodyCompact`, `label`, `caption`, `numericHero`, `numericBody`, `mono`) with font weight, line height, letter spacing, font role, and `tabularFigures`.
- **Spacing, Radii, Elevation, Breakpoints**: `spacing` (`xs..xl`), `radii` (`sm..sheet, full`), `elevation` (`none..high`), and `breakpoints` (`medium: 600`, `expanded: 840`, `maxContentWidth: 720`, `maxWideWidth: 1120`).

### 2.2 `business_rules.json` (v1.0.0 — **Implemented**)
- **Finance**: `currencyCode: "ETB"`, `minorUnitsPerMajor: 100`, integer cents enforcement, reject `<= 0` amounts, reject identical transfer accounts, transfer preserves combined balance, safe deletion guards for accounts and categories with transactions.
- **Tasks (Stage 0.2A)**: Priority weights (`urgent: 4`, `high: 3`, `medium: 2`, `low: 1`), canonical `statuses` (`not_started`, `in_progress`, `completed`, `cancelled`, `inbox`), `priorities` (`low`, `medium`, `high`, `urgent`), `recurrenceFrequencies` (`daily`, `weekly`, `monthly`, `yearly`), `recurrenceRepeatFromModes` (`due_date`, `completion_date`, default `due_date`), `recurrenceCalendarBasis: "gregorian"`, ISO weekdays (`iso_1_to_7`, `1..7`), canonical subtask keys (`["id", "title", "done"]` with `subtaskLegacyDoneAlias: "completed"`), Daily Planning uniqueness (`["taskId", "planDate"]`) and task-delete cascade (`dailyPlanningOnTaskDelete: "cascade"`), `defaultPriority: "medium"`, `defaultStatus: "not_started"`, and explicit invariant flags (`deriveReminderStateFromReminders: true`, `singleCompletionSourceInStatus: true`, `utcIsoCompletedAt: true`, `preserveMyDayPlanningHistory: true`, `separateInboxFromUnassignedTasks: true`, `uniqueDailyPlanningEntryPerTaskDate: true`, `cascadeDeleteDailyPlanningOnTaskDelete: true`), generated symmetrically into `SharedTaskContracts` (Dart) and `SHARED_BUSINESS_RULES.tasks` / `CANONICAL_TASK_*` / `PLANNED_TASK_V10_FIELDS` constants (TS).
- **Calendar**: `system: "ethiopian_dual"`, 13 months, 30 days for months 1–12, Pagume 5 days (6 when `year % 4 == 3`), `canonicalDateFormat: "YYYY-MM-DD"`, `timeConvention: "UTC+3"`, `fixedUtcOffsetMinutes: 180`.
- **Projects (Stage 1 / 1.1 & Stage 3 — [ADR-009](./decisions/ADR-009-projects-stage1-tracking-foundation-and-schema-v9.md), [ADR-010](./decisions/ADR-010-projects-stage3-portable-project-package.md))**: Statuses (`active`, `completed`, `on_hold` — separate from `isArchived`), block types (`counter`, `grouped_list`, `checklist`, `schedule`), record types (`group`, `grouped_item`, `checklist_item`, `schedule_item`, `progress_log`), custom field types (`text`, `number`, `date`, `boolean`, `select`), bounded limits (`maxBlocksPerProject: 32`, `maxCustomFieldDefinitions: 24`, `maxCustomFieldSelectOptions: 50`, `maxHierarchyDepth: 3`, `maxTrackingRecordTitleLength: 300`), append-only progress logs with explicit compensating corrections, single-source derived rollups (disallowing direct logging on rollup counters), independent multi-metric evaluation (no implicit cross-block averaging; `requiresExplicitPrimaryBlockForOverallPercent: true`), and schedule duration rule options (`manual`, `threshold_percent`, `exact_duration`), generated into `SHARED_PROJECT_RULES` (TS) and `SharedProjectRules` (Dart); plus portable package spec `projectPackage` (`formatId: "daywell_project_package"`, `currentFormatVersion: 1`, `minSupportedFormatVersion: 1`, `fileExtension: ".daywellproject"`) generated into `SHARED_PROJECT_PACKAGE_SPEC` (TS) and `SharedProjectPackageSpec` (Dart).
- **Daily Rhythm (Stage A — Pure Contracts & Streak Rules)**: `qualifyingDaysPerFreeze: 15`, `maxStreakFreezes: 2`, `maxProtectedGapDays: 1`, `dayStatuses` (`untouched`, `partial`, `complete`, `freeze_protected`, `missed`), `financeCloseStatuses` (`open`, `closed_with_transactions`, `closed_no_transactions`, `needs_reconfirmation`), `defaultFinanceCloseStatus: "open"`, and invariant flags (`requireAllThreeResponsibilities: true`, `requireBothFaithPractices: true`, `requireCompletingAllTasks: false`, `emptyFinanceDayAutoQualifies: false`, `lockPastFaithAndTaskReview: true`, `preserveFinalizedHistoryOnLedgerCorrection: true`, `useEthiopiaDateConvention: true`), generated symmetrically into `SharedDailyRhythmContracts` (Dart) and `CANONICAL_DAILY_RHYTHM_*` / `SHARED_BUSINESS_RULES.dailyRhythm` (TS).

### 2.3 `schema_contracts.json` (v2.0.0, `schemaVersion: 12` — **Implemented**)
Defines 23 canonical exchange/domain entity shapes and time convention (`Africa/Addis_Ababa`, `UTC+3`, `observesDst: false`):
- `Task` (**Persisted DB v10** Stage 0.2B fields): Retains all 17 v9 persisted fields, formalizes canonical `subtasks` items (`{ id, title, done }` with legacy `completed` / optional-`id` compatibility metadata), and defines 6 additive columns persisted in Drift v10 (`completedAt` UTC ISO-8601, `scheduledTime` `HH:MM`, `myDayDate` `Africa/Addis_Ababa` `YYYY-MM-DD`, structured `recurrenceConfig` persisted in `recurrence_config_json`, `isArchived`, and `sortOrder`; retained `"plannedDatabaseSchemaVersion": 10` annotations preserve `PLANNED_TASK_V10_FIELDS` generation). Derives reminder state solely from `Reminder` records, completion truth solely from `status === 'completed'`, keeps `'inbox'` status strictly for legacy compatibility (distinct from `InboxItem` triage), and excludes any `ProjectSection` / `sectionId` reference.
- `Milestone` (**Persisted DB v9/v10**): Kept strictly to its 6 existing persisted fields (`id`, `projectId`, `title`, `dueDate`, `isCompleted`, `createdAt`).
- `DailyPlanningEntry` (**Persisted DB v10**): Tagged `"plannedDatabaseSchemaVersion": 10`, persisted in `DailyPlanningEntries` (`daily_planning_entries`) with composite `uniqueKey: ["taskId", "planDate"]`, `"onTaskDelete": "cascade"`, and `action`: `planned | carried_forward | completed | dismissed`.
- `Note`, `CalendarEvent`, `Account` (including 11-value `subType` enum, `isSystem`, and standardized `isArchived` lifecycle per [ADR-008](./decisions/ADR-008-retire-account-isactive-and-schema-v8.md)), `Category`, `Transaction`, `JournalEntry` (including canonical `snake_case` 7-value `entryType` enum: `standard`, `transfer`, `debt_issuance`, `settlement`, `split_expense`, `adjustment`, `write_off`), `Debt` (`debtType` + canonical `snake_case` 4-value `status` enum: `active`, `settled`, `written_off`, `voided`), `Project` (extended additively with `isArchived`, `startDate`, `customFields`, `updatedAt`), `ProjectTrackingBlock`, `ProjectTrackingRecord`, `Goal`, `InboxItem`, `Commitment`, `CommitmentSettlement`, `SavingsGoal`, `Budget`, `RecurringRule`, `Reminder` (`title`, `channelId`, `targetId`, `targetType`, `triggerTimeUtc`, `isActive`, `createdAt`), `AppSetting` (`key`, `value`, `updatedAt`), and `DailyRhythmDay` (**Persisted DB v12** Stage A/B contract: `dateIso` PK, `bibleStudyDone`, `bibleStudyCompletedAt`, `prayerDone`, `prayerCompletedAt`, `taskReviewConfirmed`, `taskReviewedAt`, `taskReviewEvidence`, `financeCloseStatus`, `financeClosedAt`, `updatedAt`).
- Note: Remaining double-entry relational entities (`PartiesTable`, `PostingsTable`, `SettlementAllocationsTable`) exist in Flutter SQLite and TypeScript `SharedDatabaseStateV7` extensions rather than inside `schema_contracts.json` directly. Generated canonical enum and contract constants (`CANONICAL_ENTRY_TYPES` / `CANONICAL_DEBT_STATUSES` / `CANONICAL_TASK_*` / `CANONICAL_DAILY_PLANNING_ACTIONS` / `CANONICAL_DAILY_RHYTHM_*` / `PLANNED_TASK_V10_FIELDS` in TS; `SharedFinanceContracts`, `SharedTaskContracts`, and `SharedDailyRhythmContracts` in Dart) synchronize contract shapes across both runtimes; repository mapping and backup/snapshot payload serialization for Stage 0.2C (`v10`), Stage 8 (`v11`), and Stage B Daily Rhythm (`v12`) are implemented in parallel across both platforms (UI/module integration deferred to later stages).

### 2.4 `canonical_seed_database.json` (**Implemented**)

### Backward-Compatibility & Automated Enforcement ([ADR-007](./decisions/ADR-007-mandatory-backward-compatibility.md))
Per Constitution Section 2.11 and [ADR-007](./decisions/ADR-007-mandatory-backward-compatibility.md), new modifications to `/shared_foundation/*.json` MUST preserve existing TS and Dart consumers (for example, additive contract fields and retaining `KnownSeedIds` purge entries) or deliver coordinated migrations and parity tests across both platforms in the same stage.

Stages 3.2–3.3 enforce these guarantees via `npm run check-foundation` (`node scripts/sync_foundation.mjs --check`, run automatically by `npm run lint` and CI):
- **Non-destructive Freshness:** Verifies `src/domain/sharedFoundation.ts`, `flutter_app/lib/core/shared_foundation_core.dart`, and `flutter_app/lib/core/shared_foundation.dart` match current `/shared_foundation/*.json` specs byte-for-byte without modifying files.
- **Complete 5-File Validation:** Validates `design_tokens.json`, `business_rules.json`, `schema_contracts.json`, `canonical_seed_database.json`, and `calendar_test_vectors.json`.
- **Contract Non-Regression Baseline & Git Base Diff (Stage 3.3):** Checks protected design tokens, `KnownSeedIds` / `KNOWN_SEED_IDS`, `SYSTEM_CONTROL_ACCOUNT_IDS` / `SystemControlAccounts`, `business_rules.json` keys, and `schema_contracts.json` entities/fields/types/required flags/enums against `/scripts/foundation_compatibility_baseline.json` AND (when Git history is present or required in CI/via `--base-rev`) compares the current baseline against the authoritative Git base revision (`pull_request.base.sha` / push `before` / `HEAD^`), failing closed in GitHub Actions if history is shallow or unavailable or if callers attempt `--base-rev` override. Breaking baseline changes require `intentionalRemovals` referencing an **`accepted`** ADR under `/docs/architecture/decisions/ADR-*.md` with non-empty `## Justification`, `## Migration Strategy`, and `## Affected Consumers` sections, existing `coordinatedConsumers` files, and existing `verificationTests` files (note: structural ADR validation checks format/status/links and **does NOT replace human review and approval**).
- **Schema-Version Alignment Guard:** Enforces `flutter_app/lib/data/database/app_database.dart` (`AppDatabase.schemaVersion`) == `shared_foundation/schema_contracts.json` (`schemaVersion`, currently `10`) while leaving `canonical_seed_database.json` (`5`) and `SharedStateBridge` (`5`) intentionally untouched.
