## 1. Parity Philosophy & Reconciliation Baseline

Per Rule 2.4 of [the Project Constitution](../../PROJECT_CONSTITUTION.md) and our Governance baselines:
1. **Equivalent Product, Not Pixel Cloning:** Flutter Android (`flutter_app/`) and Google AI Studio Web Preview (`src/`) represent one product (**Daywell**). We require equivalent product identity, semantic colors/tokens (`design_tokens.json` → `SharedDesignTokens` / `--dw-*`), shared UI primitive semantics (`shared_ui_widgets.dart` ↔ `src/components/ui/`), terminology, information hierarchy, validation semantics, and core workflow behavior—while allowing deliberate platform adaptations (e.g., Material 3 `NavigationBar`/`NavigationRail` vs. Web responsive frame; native APK file sharing vs. browser `Blob` download).
2. **Default Reconciliation Baseline:** Whenever Flutter Android and Web Preview diverge without an approved exception, future reconciliation stages MUST converge toward:
   - Canonical tokens & schemas in [`/shared_foundation/`](../../shared_foundation/)
   - Visual assets & screen specs in [`/design_assets/`](../../design_assets/) (subject to approved v7 decisions via the 5-level UI hierarchy)
   - Stage 2.2 strict ETB currency isolation (approved architectural requirement) and offline-first data integrity rules
3. **Mandatory Backward-Compatible Interoperability ([ADR-007](./decisions/ADR-007-mandatory-backward-compatibility.md)):** All new cross-platform changes MUST preserve Flutter/Web canonical JSON exchange compatibility, previously released backup/snapshot compatibility through deterministic upcasting, and safe failure on unsupported future versions. Existing compatibility defects are assessed on modification or material risk rather than through blanket retroactive rewrites.

## 3. Summary of Parity Findings

1. **Strongest Cross-Platform Foundations:**
   - **Canonical Design System & Shared UI Primitives (`Implemented` across Tokens & Primitives):** Flutter (`DaywellTheme` + `shared_ui_widgets.dart` + `flutter_app/lib/ui/screens/projects/*`) and Web (`src/styles/daywellTokens.css` + `src/components/ui/` + `src/components/projects/*`) consume `/shared_foundation/design_tokens.json`, enforced automatically by `npm run check-ui`. `MoreView`, `DashboardView`, and `flutter_app/lib/ui/screens/projects/*.dart` use `DaywellTheme` with `0` raw `Colors.*` / `Color(0x...)` literals, and Web UI contains `0` hardcoded hexes.
   - **Ethiopian/Gregorian Date Math (`Implemented`, vector-verified)**, **Projects Stage 1–5 Domain, Persistence, PC/Mobile Workspace UI, `.daywellproject` Package Transfer & BIM Outreach Campaign Template (`Implemented` on Web/Node; Flutter UI/SAF/IO/template implemented with runtime/codegen CI-pending)**, and **Finance v7 / Recovery Stage 2.1–2.2 + Stage A + Stage F4 (`Partially implemented`):** Recovery Stage 2.1 is implemented and conditionally accepted. Stage 2.2 strict ETB-only isolation, Finance Stage A cross-platform enum parity (`entryType`/`debtStatus` canonical `snake_case`) + safe legacy non-ETB/unverified account preservation (`v4–v9`, `format-2`), and **Stage F4** reporting, canonical hierarchical category spend, 13-table UTF-8 BOM CSV + SQLite exports, and strict Finance-only JSON portability are **Implemented** and verified on Web/Node (`stageF4ReportingAndPortability.test.ts`), while Flutter counterparts (`DoubleEntryEngine` F4 reports, `FinanceExportService` 13 CSVs & 13-table SQLite script, `DatabasePersistenceCoordinator` Finance-only JSON snapshot export/import, `FinancePlanTab` / `FinanceReportsTab`, `finance_stage_f4_test.dart`) are implemented in code and **Unverified** locally pending CI. Recovery Stage 2.2 ETB currency isolation remains incomplete/unaccepted until full CI & device verification completes.
2. **Primary Structural Gaps Requiring Future Authorized Stages:**
   - **Finance v7 Integration & Stage 2.2 / F3 / F4 / Projects CI Acceptance:** Verify Flutter/Android Stage 2.2, Stage F3 (`finance_stage_f3_composer_test.dart`), Stage F4 (`finance_stage_f4_test.dart`), and Projects Stage 1–4 (`dart run build_runner`, `flutter analyze`, `flutter test`) in CI before marking Flutter/Android Finance parity complete.
   - **Flutter Calendar UI:** Backend/DB/controller implemented; UI remains `CalendarPlaceholderView` (intentionally preserved in the UI governance stage) while Web has a full interactive calendar.
   - **Legacy Flutter `Colors.*` Cleanup (5 Files):** Migrate remaining bounded `Colors.*` entries in `tasks_view.dart` (reduced to 19 in Stage 2), `backup_view.dart`, `notes_view.dart`, `finance_overview_tab.dart`, and `quick_capture_dialog.dart` tracked in `scripts/ui_consistency_allowlist.json`.
   - **Web Live Feature Convergence & Prototype Replacement:** Replace remaining `Deprecated Prototype` sample cards on `Today` and `Sync & backup` with live stores when scheduled; align `Quick Capture` Inbox vs. direct routing and Notes `Favorites`/`Trash`.
   - **Backup Format Convergence:** Both platforms enforce Stage 3.4.2 / 3.4.4.1 fail-closed `.daywell` format-v1 header & KDF validation plus snapshot version bounds (`4..9` on canonical snapshots, preserving pre-v9 backups with empty project tracking collections, per [ADR-008](./decisions/ADR-008-retire-account-isactive-and-schema-v8.md) and [ADR-009](./decisions/ADR-009-projects-stage1-tracking-foundation-and-schema-v9.md)), **but cross-platform encrypted payload convergence remains incomplete:** Flutter ships PBKDF2/AES-GCM-256 `.daywell` UI for canonical v9 snapshots while Web UI exposes unencrypted canonical exchange JSON (`SharedStateBridge`) and `backupCrypto.ts` remains unattached on legacy `LocalDatabaseState` v3.
   - **Flutter `MoreView` Notification Row:** Currently a silent no-op callback (`onTap: () {}`).
3. **Unverified Native Mobile Capabilities (Cannot Verify in Linux Container):** On-device Android `MethodChannel` shared-text capture (`MainActivity.kt`), `flutter_local_notifications` display/channel behavior on physical Android (`minSdk 26` / `targetSdk 34`), `sqlite3_flutter_libs` runtime migration, and APK upgrade preservation on hardware are **Unverified** locally.
